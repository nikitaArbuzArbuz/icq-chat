# ICQ Chat

Чат один на один в стиле ICQ: пользователи регистрируются, переписываются в реальном времени и видят статусы сообщений — отправлено, доставлено, прочитано. Все сообщения хранятся в PostgreSQL.

## Возможности

- Регистрация и вход по логину и паролю, авторизация через JWT (живёт сутки).
- Список контактов с поиском по логину, онлайн-индикатором и счётчиком непрочитанных.
- «Избранное» — переписка с самим собой, всегда первая в списке.
- История переписки с курсорной пагинацией: старые сообщения подгружаются при прокрутке вверх.
- Отправка сообщений через WebSocket, без дублей при повторной отправке (clientId).
- Статусы: SENT → DELIVERED → READ, обновляются у отправителя в реальном времени.
- Досылка недоставленных сообщений, когда получатель подключается: пачками по 100, следующая пачка приходит после подтверждения доставки предыдущей. Подтверждения доставки веб-клиент копит 100 мс и отправляет одним сообщением.
- При обрыве веб-клиент переподключается со случайной задержкой, растущей от 0,5–1 до 15–30 секунд, чтобы после рестарта сервера клиенты не подключались все одновременно.
- Несколько вкладок одного пользователя: сообщения, статусы и прочтение синхронизируются во всех.
- Онлайн-статус приходит только тем, кто подписан на пользователя (веб-клиент подписывается на всех из своего списка контактов); мёртвые соединения закрываются по heartbeat, сессия с истёкшим токеном тоже закрывается.
- Отправка в сокеты асинхронная: медленный клиент не тормозит остальных, а если у него скопилось больше 1000 неотправленных сообщений, сервер разрывает соединение, и клиент переподключается.
- При перегрузке базы сервер быстро отказывает, а не зависает: свободное соединение из пула запрос ждёт не дольше 3 секунд, сам SQL-запрос выполняется не дольше 5 секунд. В REST в этом случае приходит `503 SERVICE_UNAVAILABLE` с заголовком `Retry-After`, в WebSocket — ошибка с тем же кодом.

## Быстрый старт через Docker

Нужны Docker и Docker Compose.

```bash
docker compose up --build
```

После запуска:

- веб-интерфейс: http://localhost:3000
- API бэкенда напрямую: http://localhost:8080
- PostgreSQL: localhost:5432

Все переменные берутся из файла `.env` в корне, их описание ниже в разделе «Переменные окружения». В docker-compose `DB_HOST` переопределяется на `postgres`, остальное используется как есть.

Остановить и удалить данные:

```bash
docker compose down -v
```

## Как быстро проверить чат

1. Запустите проект: `docker compose up --build`.
2. Откройте http://localhost:3000 в обычном окне браузера и войдите как `alice` / `password123`.
3. Откройте http://localhost:3000 в окне инкогнито (или в другом браузере) и войдите как `bob` / `password123`.
4. У Алисы в списке контактов Боб отмечен зелёной точкой — он в сети.
5. Выберите собеседника и напишите сообщение. У отправителя сначала появится значок ожидания, затем одна серая галочка (сохранено), две серые (доставлено) и две синие, когда получатель откроет переписку.
6. Закройте окно Боба и напишите ему: сообщение останется с одной галочкой. Войдите за Боба снова — сообщение будет дослано, и у Алисы галочки обновятся.
7. Откройте вторую вкладку за Алису: отправленные сообщения и прочтения синхронизируются между вкладками.

|---|---|---|

| `DB_HOST` | `localhost` | хост PostgreSQL |
| `DB_PORT` | `5432` | порт PostgreSQL |

## REST API

Все ответы — JSON. Ошибки приходят в едином формате:

```json
{"code": "LOGIN_TAKEN", "message": "Логин уже занят"}
```

Все эндпоинты, кроме регистрации, входа и `/health`, требуют заголовок `Authorization: Bearer <token>`.

Если база перегружена (не дождались свободного соединения из пула за 3 секунды или запрос выполнялся дольше 5 секунд), любой эндпоинт отвечает `503` с кодом `SERVICE_UNAVAILABLE` и заголовком `Retry-After`: запрос можно повторить.

### Регистрация

```bash
curl -X POST http://localhost:8080/api/auth/register \
  -H 'Content-Type: application/json' \
  -d '{"login": "charlie", "password": "password123"}'
```

Ответ `201`:

```json
{"token": "eyJ...", "user": {"id": 3, "login": "charlie"}}
```

Ошибки: `400 VALIDATION_ERROR`, `409 LOGIN_TAKEN`.

Требования: логин от 3 до 32 символов (латиница, цифры, подчёркивание), пароль не короче 8 символов и не длиннее 72 байт в UTF-8. Это ограничение bcrypt: 72 латинских символа или 36 букв кириллицы. Пароль не может состоять только из пробелов и невидимых символов (неразрывных пробелов, пробелов нулевой ширины и т. п.).

Логины уникальны без учёта регистра: если есть `alice`, зарегистрировать `Alice` нельзя (`409 LOGIN_TAKEN`). Вход тоже без учёта регистра, а логин отображается так, как его ввели при регистрации.

### Вход

```bash
curl -X POST http://localhost:8080/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"login": "alice", "password": "password123"}'
```

Удобно сохранить токен в переменную (нужен `jq`):

```bash
TOKEN=$(curl -s -X POST http://localhost:8080/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"login": "alice", "password": "password123"}' | jq -r .token)
```

### Текущий пользователь

```bash
curl http://localhost:8080/api/me -H "Authorization: Bearer $TOKEN"
```

### Список контактов

```bash
curl "http://localhost:8080/api/users?search=bo" -H "Authorization: Bearer $TOKEN"
```

```json
[
  {"id": 1, "login": "alice", "self": true, "online": false, "unread": 0, "lastMessageAt": null},
  {"id": 2, "login": "bob", "self": false, "online": true, "unread": 3, "lastMessageAt": "2026-10-14T10:00:00Z"}
]
```

Первым всегда идёт текущий пользователь (`self: true`) — это «Избранное». Дальше диалоги по времени последнего сообщения (`lastMessageAt`), от новых к старым, в конце пользователи, с которыми ещё не было переписки (`lastMessageAt: null`), по логину. Веб-клиент поднимает диалог наверх при каждом новом сообщении, входящем или своём.

### История переписки

```bash
# последние сообщения
curl "http://localhost:8080/api/messages/2?limit=50" -H "Authorization: Bearer $TOKEN"

# сообщения старше id 120
curl "http://localhost:8080/api/messages/2?before=120&limit=50" -H "Authorization: Bearer $TOKEN"
```

Параметры: `before` — id сообщения, старше которого грузить (необязательный), `limit` — размер страницы (по умолчанию 50, максимум 100).

```json
{
  "messages": [
    {"id": 101, "senderId": 1, "recipientId": 2, "clientId": "c-1", "text": "Привет", "status": "READ", "createdAt": "2026-10-14T10:00:00Z"}
  ],
  "hasMore": true
}
```

Сообщения внутри страницы идут от старых к новым, `hasMore` показывает, есть ли ещё более старые.

### Проверка живости

```bash
curl http://localhost:8080/health
```

## WebSocket

Подключение: `ws://localhost:8080/ws?token=<JWT>` (через nginx — `ws://localhost:3000/ws?token=<JWT>`). Если токен невалидный или истёк, сервер закрывает соединение с кодом `4401`.

Все сообщения — JSON с полем `type`.

**Heartbeat.** Сервер раз в 20 секунд присылает каждой сессии `{"type": "ping"}`, клиент отвечает `{"type": "pong"}`. Любое сообщение от клиента продлевает сессию.

| Ситуация | Что делает сервер | Что делает веб-клиент |
|---|---|---|
| от клиента ничего не приходило 45 секунд | закрывает сессию с кодом `4408`, пользователь становится офлайн | переподключается |
| истёк срок действия токена | закрывает сессию с кодом `4401` | разлогинивается |
| от сервера ничего не приходило 45 секунд | — | считает соединение мёртвым и переподключается |

### Клиент → сервер

**Отправка сообщения**

```json
{"type": "send", "clientId": "6b1f…", "to": 2, "text": "Привет!"}
```

`clientId` генерирует клиент (например, UUID). Повторная отправка с тем же `clientId` не создаёт дубль.

**Подтверждение доставки**

```json
{"type": "delivered", "messageIds": [101, 102]}
```

Не больше 1000 id за раз. Подтверждение пачки `undelivered` — сигнал серверу прислать следующую.

**Прочтение**

```json
{"type": "read", "peerId": 1, "lastMessageId": 102}
```

Помечает прочитанными все входящие сообщения от `peerId` с id ≤ `lastMessageId`.

**Подписка на онлайн-статусы**

```json
{"type": "watch", "userIds": [2, 3, 5]}
```

Новый набор заменяет предыдущий, максимум 200 пользователей. Подписки живут, пока живёт соединение, поэтому после переподключения их нужно прислать заново. В ответ приходит `presenceSnapshot`.

**Ответ на ping**

```json
{"type": "pong"}
```

### Сервер → клиент

**Подтверждение сохранения** (только отправителю)

```json
{"type": "ack", "clientId": "6b1f…", "id": 101, "createdAt": "2026-10-14T10:00:00Z"}
```

**Новое сообщение** (получателю, если он онлайн, и в другие вкладки отправителя)

```json
{"type": "message", "message": {"id": 101, "clientId": "6b1f…", "senderId": 1, "recipientId": 2, "text": "Привет!", "status": "SENT", "createdAt": "2026-10-14T10:00:00Z"}}
```

**Недоставленные сообщения** (при подключении: всё, что пришло, пока получатель был офлайн)

```json
{"type": "undelivered", "messages": [{"id": 101, "clientId": "6b1f…", "senderId": 1, "recipientId": 2, "text": "Привет!", "status": "SENT", "createdAt": "2026-10-14T10:00:00Z"}], "hasMore": true}
```

Сообщения идут по возрастанию id, не больше 100 в пачке. Если `hasMore: true`, следующая пачка придёт, когда клиент подтвердит доставку этой через `delivered`. Если клиент не подтвердил доставку и отключился, при следующем подключении недоставленное придёт снова.

**Доставлено** (отправителю)

```json
{"type": "delivered", "recipientId": 2, "messageIds": [101, 102]}
```

**Прочитано** (отправителю и в другие вкладки читателя)

```json
{"type": "read", "readerId": 2, "senderId": 1, "upToMessageId": 102}
```

**Снимок онлайн-статусов** (в ответ на `watch`)

```json
{"type": "presenceSnapshot", "watched": [2, 3, 5], "online": [2]}
```

**Онлайн-статус** (только подписанным на пользователя, при первом входе и последнем выходе)

```json
{"type": "presence", "userId": 2, "online": true}
```

**Ping** (каждой сессии раз в 20 секунд, ждёт ответа `pong`)

```json
{"type": "ping"}
```

**Ошибка**

```json
{"type": "error", "clientId": "6b1f…", "code": "EMPTY_MESSAGE", "message": "Сообщение не может быть пустым"}
```

`clientId` есть, если ошибка относится к конкретному отправленному сообщению. Код `SERVICE_UNAVAILABLE` означает, что база перегружена и сообщение можно отправить ещё раз. Если при подключении не удалось загрузить недоставленные сообщения, сервер закрывает соединение со стандартным кодом `1013` («попробуйте позже»), и клиент переподключается.

### Проверка через websocat

```bash
websocat "ws://localhost:8080/ws?token=$TOKEN"
```

После подключения вставьте строку и нажмите Enter:

```json
{"type": "send", "clientId": "test-1", "to": 2, "text": "Привет из websocat"}
```

В ответ придёт `ack`. Если в соседнем терминале подключиться за Боба, ему придёт `message`, а после отправки `{"type": "delivered", "messageIds": [<id>]}` Алиса получит `delivered`.

Websocat сам на `ping` не отвечает: если 45 секунд ничего не отправлять, сервер закроет соединение с кодом `4408`. Чтобы соединение не закрылось, отвечайте на `ping` строкой `{"type": "pong"}`.

## Тесты

Интеграционные тесты на JUnit 5 поднимают настоящее приложение и PostgreSQL 16 в Docker через Testcontainers и общаются с ним как клиент: по HTTP и по WebSocket. Для запуска нужен работающий Docker, больше ничего настраивать не надо.

```bash
cd backend
./gradlew test        # на Windows: gradlew.bat test
```

В IntelliJ IDEA тесты запускаются зелёной стрелкой у класса или у папки `src/test/java`.

Что покрыто:

| Класс | Что проверяет |
|---|---|
| `AuthIntegrationTest` | регистрация и вход, валидация логина и пароля, пароль длиннее 72 байт, доступ без токена |
| `SendIdempotencyIntegrationTest` | повторная отправка с тем же `clientId` не создаёт дубль, в том числе после переподключения |
| `MessageStatusIntegrationTest` | статусы SENT → DELIVERED → READ без отката и без лишних уведомлений, чужие сообщения не подтвердить |
| `HistoryPaginationIntegrationTest` | пагинация истории: `before`, `limit`, `hasMore`, максимум 100, посторонний не видит переписку |
| `OfflineDeliveryIntegrationTest` | досылка недоставленных сообщений пачками: порядок, повтор до подтверждения, следующая пачка только после подтверждения |
| `OnlineDeliveryIntegrationTest` | доставка онлайн-получателю и синхронизация вкладок (регрессия NPE при рассылке) |
| `PresenceIntegrationTest` | онлайн-статус только подписчикам, снимок при подписке, несколько вкладок |
| `FavoritesIntegrationTest` | «Избранное»: сообщения себе сразу прочитаны и не досылаются |
| `ContactsOrderIntegrationTest` | порядок контактов: «Избранное» первым, дальше диалоги по последнему сообщению |
| `DatabaseIntegrationTest` | таймауты пула: statement_timeout на соединениях, прерывание долгого запроса, быстрый отказ при исчерпании пула |
| `InvisibleTextIntegrationTest` | сообщения и пароли из одних невидимых символов (неразрывные пробелы, пробелы нулевой ширины) отклоняются |
| `TextsTest` | модульный тест проверки «визуально пустого» текста, Docker не нужен |

## Известные ограничения

- JWT нельзя отозвать до истечения срока: выход из аккаунта только удаляет токен на клиенте.
- Сервер хранит сессии в памяти, поэтому рассчитан на один экземпляр бэкенда.
